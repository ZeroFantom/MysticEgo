# Обновления MysticEgo из GitHub

В Orchestra откройте **Ветки GitHub → Обновление сервера** под главным
разработчиком. Панель показывает установленные версии и предлагает три
операции, когда для обеих панелей есть новая сборка.

- **Обновить Orchestra** заменяет сборку Orchestra и сохраняет установленную версию Audit.
- **Обновить Audit** обновляет локальный веб-портал без перезапуска Orchestra.
- **Обновить Orchestra + Audit** применяет обе части релиза одной операцией.

Служба проверяет размер и SHA-256 пакета, сверяет версию и проверяет health
с прежним ID. При сбое возвращается предыдущая сборка. Данные и настройки
Auth остаются вне каталога приложения. Перед релизом с миграциями сохраните
резервную копию базы.

Обновление работает для встроенного Audit и для собственного домена Audit,
размещённого на том же VPS и подключённого CloudDesk R3.2.5 или новее.
Для домена, настроенного предыдущим установщиком, один раз повторите
**Обновление узлов → Веб-панель Audit → На отдельном домене** в CloudDesk.
Отдельный VPS Audit обновляется из CloudDesk через этот же раздел.

## Подключение на действующем VPS R3.1

Перенесите на VPS каталог `ops/orchestra-updater` из готового архива.
На сервере нужны Python 3, GitHub CLI, curl и действующий
`mysticego-orchestra.service`. Для приватного репозитория подготовьте токен
GitHub с правом **Contents: Read** только к `ZeroFantom/MysticEgo`.
Запишите переменную `GH_TOKEN` в `/etc/mysticego/orchestra-updater.env`
с владельцем root и правами 0600. Затем из перенесённого каталога:

```bash
sudo bash bootstrap-r31.sh
```

Сценарий сверяет SHA-256 установленной DLL. Журнал обновления доступен через
`sudo journalctl -u mysticego-orchestra-updater.service -n 60 --no-pager`.

## Публикация следующей версии

После сборки полного ZIP подготовьте Linux-пакет и прикрепите его к релизу:

```bash
python3 prepare-release.py MysticEgo-next.zip
gh release upload <тег> MysticEgo-Orchestra-linux-x64.zip --repo ZeroFantom/MysticEgo
```

Служба выбирает пакет с SHA-256 среди 30 недавних опубликованных релизов.
Поддерживаются предварительные релизы. Тег начинается с v и цифры.
Будущие обновления подтверждаются в веб-панели.

## Пароль developer в CloudDesk

После входа developer в **Инфраструктура → Источник инфраструктуры** нажмите
**Показать пароль developer**. Требуется доверенный SSH под root к тому же Orchestra.
CloudDesk сверяет локальный ID и проверяет пароль в Auth. Пароль автоматически
скрывается через 20 секунд и не сохраняется в настройках или журнале.
