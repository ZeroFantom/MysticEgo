# GitHub и локальный помощник Orchestra

Во всех веб-панелях **Установлено** показывает метку сборки из
`release-info.json`, а **GitHub** показывает последний опубликованный релиз
из выборки GitHub, включая предварительные. Чтобы эти значения совпали,
прикрепите собранный архив к релизу с тегом из его метаданных.

Orchestra обслуживает панель веток и публичный endpoint версии.
Для частного репозитория укажите `PanelGitHub__Token` с правом чтения Contents
в защищённом файле окружения Orchestra. Токен хранится на сервере.
Список веток виден владельцу и утверждённым участникам команды.
На отдельных узлах адрес центрального источника можно задать полем
`releaseOrigin` в их `release-info.json`.

## Модель на VPS Orchestra

В **Ассистенте** находятся личный чат, характер, помощь разработчику и
управление моделями. Вкладки разработки и администрирования доступны
по ролям. По умолчанию помощник разработчика использует ту же локальную
LM Studio, что и личный чат. Модель также доступна пулу WorldAI.

На новой Orchestra, развёрнутой CloudDesk, установка llmster и модели
Qwen3 1.7B GGUF Q4_K_M запускается в фоне. Для действующего VPS один раз
выполните **Обновить Orchestra** из CloudDesk R3.2.9. Настроенные ранее
модели сохраняются. Для отключения следующей автоматической установки
задайте `MYSTICEGO_DEFAULT_MODEL=off` в окружении Orchestra.

```bash
sudo journalctl -u mysticego-default-model -n 80 --no-pager
sudo systemctl status mysticego-lmstudio
```

## Отдельная модель разработчика

Установите совместимые `llama-server` и модель GGUF. Передайте пути к файлам
на этом VPS. Из каталога `ops/panel-assistant` выполните:

```bash
sudo bash install.sh /path/to/llama-server /path/to/model.gguf
```

Если сборке нужны динамические библиотеки, установите их на VPS
согласно её документации. Модель работает как отдельная служба systemd
на loopback `127.0.0.1:1236`. Для Docker Orchestra требуется сеть хоста.
В защищённом окружении Orchestra, например в `/etc/mysticego/orchestra.env`,
задайте `PanelAssistant__Model=orchestra-panel` и перезапустите Orchestra.
Установка модели и бинарника выполняется один раз на VPS. В ZIP входят
настройки службы и код интеграции.

## MCP

HTTP MCP находится на `/api/v1/managed/panel-assistant/mcp`.
Используйте короткоживущий токен аккаунта разработчика MysticEgo.
Пример настройки HTTP-клиента находится в `mcp.example.json`.

| Инструмент | Действие |
| --- | --- |
| `panel_overview` | Сводка зарегистрированных Global |
| `panel_latest_release` | Последний опубликованный релиз GitHub |
| `panel_branches` | Ветки проекта |
| `panel_open_view` | Предложение открыть один из разделов панели |

Панель выполняет переход только после нажатия пользователем кнопки.
Функции изменения VPS, учётных записей и конфигурации остаются в штатных
разделах панели и защищены их собственными проверками прав.


## Локальный Computer Use (экспериментальная ветка)

MCP-инструменты Orchestra выше не заменяют локальное управление графическим интерфейсом. [PR #72](https://github.com/ZeroFantom/MysticEgo/pull/72) добавляет отдельный исполнитель Playwright и локальный мост Agent/Audit с разрешениями владельца. Он должен работать на ПК пользователя в интерактивном сеансе Windows или Linux X11 (KDE Plasma в приоритете), а не на VPS Orchestra. Не публикуйте loopback MCP во внешнюю сеть и не отключайте авторизацию LM Studio.

- [Настройка MCP/REST исполнителя](../../tools/MysticEgo.UiAutomation/README.md)
- [Agent / Audit: разрешения, запись и системные операции](../../docs/agent-audit-computer-control.md)
- [Переход VRM Web → Desktop](../../docs/local-desktop-handoff.md)

Полная маршрутизация команд встроенного ассистента Orchestra, автоматический запуск исполнителя из настольных приложений и независимое управление курсором пока не завершены. Экспериментальная ветка требует проверок перед публикацией.
