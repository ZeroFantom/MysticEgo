SSH-статус выбранного хоста проверяется примерно каждые 15 секунд после успешного входа, при отклонении ключа повторные проверки прекращаются до нового подключения (защита от перебора). Журнал команд обновляется по завершении операции, а не построчно. Список VPS ограничен 100 записями.

По умолчанию: Orchestra, Ubuntu 24.04, root:22, автоматическое создание/регистрация SSH-ключа. Рекомендуется самый дешёвый подходящий тариф с >=2 vCPU, >=4096 МБ RAM и >=40960 МБ диска; при отсутствии таких тарифов выбирается дешевейший подходящий. Это стартовая конфигурация, не гарантированный минимум MysticEgo. Изменения выбранного тарифа не подменяются автоматически. Цена в час берётся из API, если есть; иначе ориентир (месячная цена / 730) явно отмечен приблизительным. Реальные списания, дополнительные услуги и налоги определяет Timeweb.

Обычный заказ: каталог допускает тарифы без поля доступности, но не выдаёт их за гарантированно свободные мощности. Исключаются явные признаки предзаказа, отключения, GPU и ARM. Перед созданием повторно проверяются тариф, цена и ОС. При неизвестной доступности требуется подтверждение обычного создания. Отдельный предзаказ не вызывается, но публичная схема не позволяет гарантировать внутреннее поведение провайдера при отсутствии мощностей. Не выполняются автоматические повторные POST. Global требует проверенный установочный скрипт. Токены не отправляются на VPS.

Источники: https://timeweb.cloud/tutorials/servers/kak-upravlyat-parkom-serverov-s-pomoshchyu-api ; https://timeweb.cloud/docs/cloud-servers/manage-servers/server-configuration ; https://github.com/timeweb-cloud/terraform-provider-timeweb-cloud/blob/main/docs/data-sources/presets.md .

## 0.3.5 — Auto Discovery / DNS

Автообнаружение Orchestra: каждые 60 секунд после завершения запроса, до 80 имён из Timeweb (домены, поддомены, DNS-записи до 20 зон, IPv4 включённых VPS из первой страницы), HTTPS с проверкой сертификата, без токенов. Один подтверждённый ID выбирается автоматически, несколько требуют выбора. Неизвестный адрес, невалидный сертификат или неполный список могут помешать обнаружению. Для закрытого реестра требуется обычный вход MysticEgo.

Имена: orchestra, orchestra-001 при конфликте; global-001, global-002 и т.д. Выбор по реальному каталогу DNS и поддоменов; существующая запись с совпадающим IP может быть повторно использована. При нескольких доменах приоритет — зона обнаруженного Orchestra, затем имя с mysticego, затем первая по алфавиту. Домен можно изменить. Полный DNS автоматизирован в Quick Deploy.

Раздел «Домены и DNS»: пользовательские DNS записи с ID, обновление каждые 30 секунд. Удаление только явно отмеченных A/AAAA/CNAME после подтверждения, с повторным сравнением ID и данных. Не удаляет корень зоны, wildcard, имена проекта и обнаруженных узлов, MX/TXT/NS и остальные типы. Неизвестные записи не считаются ненужными автоматически. При частичной ошибке выводится число подтверждённых удалений. Реальные DNS операции не проверялись в среде разработки.

## 0.3.8 — GitHub resilience
Профиль и доступ к приватному репозиторию проверяются через REST в C# HttpClient с локальным `gh auth token`; токен не передаётся в renderer или журнал. Убраны GraphQL и сетевой `gh auth status` из предварительных проверок. При временной сетевой ошибке локальная сессия сохраняется, ранее полученный профиль отмечается как устаревший, опрос повторяется с увеличенным интервалом. При HTTP 401 необходим повторный вход; при 403/404 не выдаётся ложное подтверждение доступа. Rate limit учитывает Retry-After/Reset. Загрузка релиза всё ещё выполняется gh CLI с проверкой SHA-256; сетевые сбои физической сети, DNS, прокси и VPN приложение не исправляет. Никакого отключения TLS-проверок или изменений системной сети. `bash github-network-check.sh` создаёт локальный отчёт без токена; HTTP 401 в анонимной проверке означает, что TLS и HTTP работают. C# сборка и восемь проверок классификации HTTP/приватности выполняются при обновлении.

## 0.3.9 — SSH key / order safety

Timeweb POST /api/v1/ssh-keys теперь явно получает boolean `is_default: false`. Существующий совпадающий ключ по-прежнему используется повторно. Ошибки подготовки заказа (каталог, GitHub, SSH-ключ) возвращают `orderState: not_sent`, без блокировки нового заказа. Ошибки с момента отправки POST /servers по-прежнему требуют проверки VPS и подтверждения, автоматического повтора нет. В update.sh добавлены пять проверок сериализации ключа и разделения этапов заказа без сети.

## 0.4.0 — Capacity fallback
Только точный HTTP 400 / POST /api/v1/servers / servers_is_run_out_error считается подтверждённым отказом по мощности. Локация исключается на 15 минут в текущей сессии; каталог и backend повторно проверяют фильтр. При выборе другого тарифа требуется новое подтверждение цены, автоматических платных повторов нет. Сетевые тайм-ауты, ошибки после создания VPS и иные неопределённые результаты сохраняют блокировку. После перезапуска приложения временный список отказов очищается.

## 0.4.1 — No free node
HTTP 409 / POST /api/v1/servers / no_free_node обрабатывается как явный отказ в создании VPS. На 15 минут исключается конкретная пара зона:ID тарифа, не вся локация. Для HTTP 400 servers_is_run_out_error сохраняется исключение локации. После явного отказа выбирается следующий подходящий тариф, без повторного платного запроса до нового подтверждения. Другие HTTP 409, тайм-ауты и сбои после создания остаются неопределёнными; защита от дублирования сохранена. Временные исключения действуют в текущей сессии. Добавлены 7 проверок к order.selftest (всего 21).

## 0.4.2 — отклонённый тариф

`404 preset_not_found` при `POST /api/v1/servers` теперь считается явным отказом: ID тарифа исключается во всех локациях на 15 минут (в текущей сессии backend), каталог немедленно перечитывается, а следующий подходящий тариф выбирается без автоматического платного заказа. `400 servers_is_run_out_error` и `409 no_free_node` работают как прежде. Неизвестные коды, тайм-ауты и ошибки после получения ID VPS по-прежнему требуют проверки списка серверов. Приложение не гарантирует наличие мощности и не отправляет предзаказ. Добавлены 10 тестов классификации и фильтрации; установщик ожидает 31 успешный тест OrderSelftest.

## 0.4.4 — проверка локаций и контрактов API

Каталог проверяется по GET /api/v2/locations и GET /api/v1/presets/servers; тарифы с отсутствующей локацией или явно указанной зоной, не принадлежащей локации, исключаются до покупки. При ошибке получения/разбора списка локаций заказ не отправляется. Список локаций не является измерением остатка мощностей. `availability_zone` передаётся только если её вернул тариф; регион не подставляется вместо зоны.

HTTP 409 `location_not_available` от POST /api/v1/servers — явный отказ; исключается выбранная зона или локация на 15 минут. Другие подтверждённые отказы обрабатываются как раньше. Каталог немедленно перечитывается, платный повтор требует подтверждения. Другие коды, тайм-ауты и ошибки после создания остаются неопределёнными. Тарифный режим сохранён, конфигуратор не добавлен.

Проверены официальные модели SDK: https://github.com/timeweb-cloud/sdk-go/blob/main/docs/LocationsAPI.md ; https://github.com/timeweb-cloud/sdk-go/blob/main/docs/LocationDto.md ; https://github.com/timeweb-cloud/sdk-go/blob/main/docs/ServersPreset.md ; https://github.com/timeweb-cloud/sdk-go/blob/main/model_create_server.go . Установщик запускает 39 тестов безопасности заказа, 17 тестов каталога/локаций и 6 тестов диагностики.

## 0.4.5 — удаление отдельных DNS-записей
Устраняет ошибку «У дублирующего имени есть другие DNS-записи». Превью и подтверждение содержат конкретные ID, имена, типы и IP удаляемых записей. Удаляются только A/AAAA проектных дублей, подтверждённые на выбранном VPS; остальные записи и сами поддомены сохраняются. Проверяются доверенный SSH, привязка роли, защищённые имена реестра, основная A-запись и повторное чтение записей перед удалением. При изменении набора записей операция отклоняется до удаления. Установщик ожидает 14 проверок binding.selftest; реальные облачные операции не выполнялись.
