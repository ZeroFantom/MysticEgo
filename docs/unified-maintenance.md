# Unified maintenance, automatic updates and runtime self-diagnostics

Owner-only Orchestra page: Infrastructure / Services. The same controls are shown under GitHub releases. CloudDesk uses the HTTPS maintenance plan after verifying the selected Timeweb VPS and its Orchestra ID with trusted SSH; normal monitoring does not repeatedly use SSH. Legacy R3.2.38 server support uses existing release/maintenance APIs, with fixed SSH recovery only when the maintenance socket is absent.

- GET /api/v1/orchestra/update/plan: fresh release and component observations, fixed systemd lifecycle/resource metrics, host CPU/RAM/network.
- POST /api/v1/orchestra/update/plan: exact action and release digest, explicitly confirmed. Reject healthy, unknown, busy or changed state. Existing update worker verifies candidate against GitHub again and rolls back failed application activation.
- GET/POST /api/v1/orchestra/update/automatic: owner-confirmed opt-in, disabled by default. The root-owned worker checks the exact fixed policy, selects only the newer verified Orchestra release, skips active infrastructure provisioning and does not automatically retry an attempted release tag after failure. Manual retry still requires confirmation. Disabling stops future automatic starts, not an already running installation. Automatic updates cover Orchestra, not independent desktop or remote node packages. No unsigned arbitrary packages, shell commands or cloud charges.
- The host sampler reads fixed cgroup v2 CPU/memory/tasks and nonprivileged systemctl show every five seconds. Orchestra and Auth share a systemd group; optional inactive units, unavailable counters, other platforms or nonstandard cgroup paths remain unknown. These are bounded measurements, not GPU or per-container metrics. Remote peers show configured HTTP health only.

Reports: GET /api/v1/orchestra/diagnostics/report?format=xlsx&scope=all. Formats xlsx/json/txt. Scope all, a known component (lmstudio, voice, auth, database, docker, etc.) or fixed systemd unit. XLSX uses inline strings, not formulas. Summary, checks, unit state and CPU/RAM/tasks; consolidated report also includes host resource history and anonymized peer links. No credentials, tokens, raw logs, arbitrary paths or user data. Service resource counters are current snapshots; not a durable time-series database.

Runtime tests: Infrastructure / Автотесты at /infrastructure/self-tests. The read-only background checker evaluates cached DB, peer health, model/voice/Docker/PostgreSQL readiness, maintenance timer/socket status and telemetry freshness every 15 seconds. UI polls every five seconds. Up to 240 cycles (approximately one hour) in memory. GET /api/v1/orchestra/self-tests and /self-tests/report?format=xlsx (under /api/v1/orchestra). Pass/fail/unknown/skip are distinct. Destructive registration/session/device tests, actual inference/transcription, GitHub writes, cloud spending and failover are explicitly skipped in production; full CI and staging remain mandatory. No arbitrary command execution.

Linux provisioning: Ubuntu 24.04+ version gate, libatomic1 checked before llmster. Ubuntu/Kubuntu desktop asks graphical PolicyKit approval for missing libatomic1 only; existing API token can be supplied via MYSTICEGO_LMSTUDIO_TOKEN environment (not included in reports). No disabling LM Studio authentication or root-running its daemon. Windows x64 uses existing SHA-512-pinned official archive; other architectures need a verified package. Real future Ubuntu distributions, KDE X11 and Windows model loads require platform acceptance tests. Native automation remains Windows/X11 only.

Release gate: publish a new versioned release after build/test validation. R3.2.38 already installed does not contain this new UI. No live VPS mutation, package purchase or deployment is performed by this change.
