# Local web to desktop delegation

Agent/Audit browser panels and desktop clients are two views of the same local node, not independent privileged runtimes.

## VRM prototype

Local authenticated owner on the node's own loopback web origin requests walk/perch. Node maintains one short-lived handoff. AgentDesktop/AuditDesktop polls using its signed-in owner's token, claims once, confirms via native dialog and launches the existing companion. Browser sends normalized horizontal scene position, never screen coordinates, bearer tokens or native commands. The desktop companion obtains the already authenticated station token through a private child stdin pipe (not a URL or command argument) and loads the existing account model and clips through normal API. It appears without taking focus where the platform honors showInactive; physical mouse/keyboard are not injected. Browser hides its stage after desktop reports startup readiness; native avatar remains independently closable. The request now carries the source motion phase in seconds if the requested motion matches the currently playing motion, plus visual mood. Destination waits for the model and assigned clips and renders before acknowledgment. The phase is sampled at request time, not synchronized at a shared final-frame timestamp. It is not frame-exact VRMA playback synchronization. Current desktop position is relative to the display work area, not an exact browser-edge crossing. Browser can restore its stage manually, but that does not close the desktop companion.

Routes: POST /api/v1/managed/avatar-handoff/request, GET /api/v1/managed/avatar-handoff/{id}, POST /api/v1/managed/avatar-handoff/claim, POST /api/v1/managed/avatar-handoff/{id}/complete. No remote/LAN requests, device tokens, forwarded requests, guest sessions or cross-origin browser calls. Explicit owner identity must be configured via UiAutomation__Owner or MYSTICEGO_AGENT_OWNER_USER. Station must already be open and authenticated with same owner, local node healthy; companion must not already be running. Native dialog is required every time. Request expiry is 60 seconds; desktop startup has an 18-second readiness timeout. No browser token is forwarded to the station. No arbitrary URL, filesystem path or executable accepted in the request.

Try in local Agent/Audit assistant: click На рабочий стол, or send exact phrases «Выйди из браузера», «Пройдись по рабочему столу», «Сядь на панель задач». Other prompts continue through normal assistant chat. Browser scene remains until acknowledgment. Desktop user may decline or close companion. Source code only; interactive validation required on Windows and KDE X11.

## General native routing (next implementation)

Use a typed action envelope with target node identity, authenticated account, expiry, required scopes, request ID, and status. Browser-capable work stays in browser. Native-only work becomes a request to the desktop client on that node. Desktop checks owner, session consent, supported platform, scope, target and local lease, then dispatches a typed allowlisted action through native adapters; return result/denial/unsupported to the web panel. No silent fallback to physical input, no arbitrary shell, no remote forwarding by default. General native delegation, MCP/workbench routing, reverse VRM transfer, frame-exact animation time/pose synchronization and multi-display browser edge mapping are not implemented by the VRM prototype.
