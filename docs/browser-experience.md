# Browser compatibility, privacy and Desktop sign-in

The login UI recognizes Mozilla Firefox, Yandex Browser, Microsoft Edge and Google Chrome using user-agent/client hints, with a separate Electron compatibility path for our desktop clients. Recognizable unsupported browsers display a blocked login notice. This is a compatibility gate, not authentication; user-agent strings may be spoofed and some derivatives are indistinguishable. Public studio, developer, downloads and sharing pages remain readable regardless of browser. Firefox-specific CSS and OS reduced-motion preferences are honored. Native browser features still require cross-browser testing.

Privacy: first visit displays a versioned origin-local consent record in localStorage, remembered across sign-in/sign-out and reload. The necessary browser/session data are separate from optional Desktop discovery; no analytics or advertising cookies are added. The persistent privacy control changes or withdraws consent. Clearing browser storage or another browser/profile/origin requires a new choice.

Desktop pairing requires HTTPS, an active user session in a running AuditDesktop, AgentDesktop, LocalDesktop or CloudDesk connected to exactly that origin, plus explicit permission on both sides. Enable MysticEgo → Предлагать вход в браузере in the native application menu and permit Desktop discovery in the website privacy settings. The login page checks four fixed loopback endpoints after five seconds; no offer if absent, denied or expired. A browser may require local network permission or prohibit the request. Installed but closed applications cannot be detected by web pages. LocalDesktop currently binds to its authenticated Global origin only; no cross-origin account transfer. The native app asks for confirmation. The browser creates a random verifier, the app exchanges its existing refresh proof with Auth over HTTPS, and the server issues a 60-second, single-use code bound to the verifier hash. Redemption checks the source refresh session is still active and creates a separate browser session, never copying the Desktop token or password. The browser confirms the returned account before accepting the session. Code storage is bounded and in-memory; a restart invalidates grants. Local bridge listens only on 127.0.0.1, exact Host and configured HTTPS Origin, no cookies, no arbitrary commands, no account details in availability. Source refresh proofs are never exposed by local HTTP. Existing browser auth storage is unchanged by this feature; secure-cookie migration remains separately tracked. The live consent and native dialog are not proof against a compromised local machine or XSS.

SEO: public Orchestra pages /studio, /developer, /desktop-downloads have static readable fallback HTML, descriptions, canonical URLs and OG metadata. The server generates sitemap.xml and robots.txt from trusted configured HTTPS PublicUrl. API/hub/MCP paths are excluded from crawler directives; private SPA routes are noindex. No cloaking based on user-agent. Submit the sitemap to Google Search Console and Yandex Webmaster after domain ownership verification; indexing/ranking are not guaranteed.

Update UI: the same tracker is used by the unified maintenance button. It distinguishes accepted, unavailable, confirmed and failed states; after a network failure it polls but does not resend the update. The tracking interval is bounded at 20 minutes, and stopping tracking does not cancel server work.

Release gate: run AuthSmoke, browser compatibility checks, loopback tests and visual smoke. Real native confirmation, browser local-network restrictions and cross-platform pairing require staging acceptance. New Auth, Distributed, UI and desktop packages must be released together. No server deployment is performed by this change.
