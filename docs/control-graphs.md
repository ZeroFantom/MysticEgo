# Control graphs and service operations

Infrastructure / Services is the full-width maintenance center. GitHub branches contains repository metadata and a link to maintenance, not a duplicate dashboard. Automatic Orchestra updates are always on; old auto-update.json files are ignored and the previous mutation API rejects changes. The worker retains version/digest validation, locking, rollback, no automatic repeat of a failed tag, and avoids active reconciliation. Existing R3.2.39 installations must receive this version once before the new default takes effect; no live host changes are made by this PR.

- Macro: registered server nodes; configured upstream links are dashed, fresh check-in links to Orchestra are solid. This is not packet capture or a physical network map. 
- Micro: local services, web panels and registered remote APIs in one graph. Local dependency arrows are architectural, not observed per-request traces. Local statuses are derived from maintenance and systemd samples; remote status comes from station reports. Unknown or stale data are not marked healthy. Remote per-process counters and automatic service discovery are not implemented here.
- Business: existing organization/club/workstation hierarchy with node management retained. All three graphs support curved links, drag, keyboard arrows, zoom and reset. Positions are local to the account/browser. Graphs use bounded display limits, and business filtering remains available.

Service load distinguishes live CPU share, current RAM/tasks, idle oneshot and non-process timers/sockets. Updater and reconcile publish last-run CPU time, peak memory, duration and result via a fixed best-effort ExecStopPost recorder in their own cgroups. Recorder data is bounded, root-owned and persists across Orchestra restarts. Missing accounting is null, not fabricated. CPU time includes cgroup work up to collection; duration is systemd main execution duration. Some kernel/systemd configurations may not expose memory peak or CPU counters. Reports retain the existing three formats and add last-run fields. Unit loads are group totals (Orchestra/Auth share a group). No remote shell commands or raw logs are exposed.

Tests: build UI, run visual regression, diagnostic smoke, updater/infrastructure tests and CloudDesk builds before releasing. Real VPS accounting and all browser themes need acceptance checks.
