# MysticEgo BETA7 R3.2.40 — изменения для следующего релиза

## Настольные приложения

- Agent Desktop и Local Desktop: проверка и скачивание обновлений без входа в аккаунт, установка и перезапуск без диалога MysticEgo. Критические операции регистрации и настройки должны завершиться до перезапуска.
- Audit Desktop и CloudDesk: скачивание без входа, подтверждение установки с описанием изменений новой версии.
- Agent, Local и Audit: карточка «Что нового» после установки, которую можно закрыть; просмотренная версия запоминается.
- Проверка точного продукта, платформы, размера и SHA-256 установщика; существующие профили сохраняются.

## Веб-панели и Orchestra

- Orchestra, Global, Local, Agent и Audit: карточка «Что нового» для фактически загруженной сборки. При смене версии на сервере открытая вкладка предлагает обновить страницу.
- Orchestra: принудительная переустановка и проверенная последовательность предыдущая → текущая → следующая версия. При понижении требуется подтверждение совместимости схемы БД и резервной копии; БД автоматически не откатывается.
- Исправления загрузки профиля и уведомлений, совместимости прежних данных и диагностики ошибок хранилища.

## Инфраструктура и разработка

- Capacity: сбор и анализ ресурсов, независимый анализатор, защищённые браузерные сессии и запуск подготовленного резервного сервера с подтверждением. Полное HA-переключение пока не реализовано.
- Development Workspace: выбор категории обсуждения GitHub, ручное восстановление связи после неопределённого результата публикации с проверкой исходного заголовка и текста.
- MCP: видимая навигация по разрешённым элементам и завершение сессии через Escape.

## Дополнительно проверяется в PR #72

- Локализация, настройки аккаунта и стабильное сохранение темы при неполном ответе Auth.
- Экспериментальные нативные операции Windows/X11, локальный исполнитель MCP, VRM handoff и управление сеансами. Проверить итоговый статус PR и провести испытания перед включением в выпускаемую сборку.

Публикация релиза, реальная проверка на VPS и проверка обновлений на физических Windows/Linux устройствах выполняются отдельно. Системные разрешения Linux не обходятся.
